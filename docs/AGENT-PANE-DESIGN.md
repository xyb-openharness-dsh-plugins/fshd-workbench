## 2. 版式与状态

业务主区在 `customFrame` 主内容内保持左/中列，Agent 为最右侧独立列。默认关闭；按钮位于顶栏右侧，标签“AI 助手”，可访问名称“打开 AI 助手”；打开时为“隐藏 AI 助手”。旁边提供持续可见的状态说明。

宽窗口：默认面板宽35%，用户可拖到25%–45%；独立竖向 `separator` 支持方向键每次1个百分点、Home/End到边界，并更新 `aria-valuenow`。拖动只改 UI 展示状态，不写患者数据。隐藏只收起右栏，重开回到同一模拟面板；本原型不宣称复用了真实会话。

容器宽度620–760px：业务顶栏可换行，导航文字保留。低于620px：面板折叠，工作台仍可用，按钮保留并说明需扩大工作区后打开；不覆盖业务内容。窄宽状态由工作台容器实际宽度驱动，不以整窗媒体查询代替。

配套可交互状态稿：默认关闭、已打开35%、宽度25%与45%、拖动、收起重开、正在连接、失败/不可用、宿主草稿冲突（保留草稿、阻止覆盖/发送）及窄屏折叠。所有内容明确标注“宿主模拟 / 非真实 DSH 会话”。状态稿不复制消息列表或输入框。

## 3. 原生宿主接入边界

当前官方合同说明：`customFrame` 可将宿主传入的 `conversation` 节点放入业务布局；会话首次创建/恢复、owner校验、草稿写入与提交须使用目标 Desktop/Harness 公开 API。已查本地官方快照（2026-10-09）；联网尝试获取官网 Markdown 被工具拒绝解析 `text/markdown`，未获得新内容。目标版本仍待核实。同机另一工作台源码有 `App({ service, entry, conversation })` 并把 `conversation` 渲染进面板的先例；它只能作为本机参考，不能证明本项目目标宿主版本支持相同 props/API。

因此 HTML 阶段只展示右侧 slot 的状态草图，不自建聊天、不伪造已连接/已发送/已回复，也不猜会话属性名或 API。实现时再针对实装依赖及目标 Desktop 类型/文档核验插槽；无可用 API 时保留业务区和可解释失败状态。

上下文草稿遵循医疗隐私边界：只允许用户选择已确认事实，展示来源、日期、核实状态和缺项；家系、心理私密记录、导入候选默认排除。任何草稿先预览；宿主已有草稿/附件时不覆盖、不合并、不自动发送。AI输出留在原生会话，由用户决定是否另行记录。

## 4. 数据和恢复

面板展开、宽度是展示偏好；原型仅内存态。生产版持久化位置/键尚待数据合同确认。宿主会话ID/owner只属宿主工作台绑定，不写患者事实表；一次性草稿默认不长期保存。隐藏不清除业务筛选、页面位置或草稿。切换业务患者不得自动切换/串联宿主会话或资料目录。
